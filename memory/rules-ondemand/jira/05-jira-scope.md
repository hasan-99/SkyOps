# Complete the agreed scope of the current Jira

Complete all acceptance criteria that belong to the agreed scope of the current Jira.

Do not create or suggest a follow-up Jira merely to move unfinished work elsewhere, unless the user explicitly decides to split the scope.

If an acceptance criterion is blocked, contradictory, obsolete, technically invalid, or genuinely outside the agreed implementation boundary, **report that clearly** instead of forcing an incorrect implementation or silently creating follow-up work.

**Why:** the pattern being prevented is the easy criteria getting done and the awkward ones being quietly spun out into a new ticket. Scaling the work down is the user's call, not an implementation detail. Naming a real blocker is not the same as deferring work — the first is required, the second is not allowed.
