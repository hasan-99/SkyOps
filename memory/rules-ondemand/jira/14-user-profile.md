# Working with Hasan

Hasan is a backend developer (C#/.NET 6) at Odyssey Cybersecurity, working the ClearSkies / CS_Datafactory_v2 stack.

## What counts as a "hard" Jira

Do **not** equate difficulty with description length or code density. A pinned bug with a code snippet and a `file.cs:line` is **easy** for him — the code shows exactly what to change.

**Hard = judgment-heavy, not code-heavy.** The hard tickets are refactors, spikes, "verify across ALL X" tasks, architecture / decoupling work, and anything whose ask is a decision spread across other tickets rather than a single line to change.

Signals of a hard ticket: many `CLS-####` cross-references you must go read; the words refactor / decouple / spike / verify / reconcile / blocked-on / open-question; unrenderable mermaid diagrams; vague "done" criteria; placeholder refs like a literal `CLS-XXXXX`.

When scoring hardness, weight prose, judgment and the cross-ticket web — and **penalise** code density, because code means clarity for a developer.

**Why:** he wants to understand the problem, the change, and the outcome quickly and stay in control of the implementation, rather than rely on an AI-generated plan.
