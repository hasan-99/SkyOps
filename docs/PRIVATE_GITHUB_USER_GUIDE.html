CopilotOps Framework

Private GitHub User Guide

Simple steps for invited users who accepted the repository invite and need to use CopilotOps safely.

Use this guide if you want the easiest path: accept the GitHub invite, open your project, run a dry-run install, then apply it if the result looks correct.

Quick Start

  1. Accept the GitHub invite to CopilotOps.
  2. Make sure Git and Node.js are installed.
  3. Open the target project folder.
  4. Run a dry-run install.
  5. Review the output.
  6. Run the real install if it looks safe.
  7. Open GitHub Copilot in the project and test the prompts.

What You Need

  • GitHub invite accepted for the private repo.
  • Git installed on your machine.
  • Node.js 18 or newer.
  • Access to the target project folder.
  • GitHub sign-in in VS Code or Git authentication already set up.

Step-by-Step

1. Accept The Invite

Open the GitHub invitation email or the repo page and accept access to the private repository.

After acceptance, you should be able to open the repo page in your browser without being blocked.

2. Check Tools

Confirm Git and Node are present before you try the command.

git --version node --version npm --version

3. Open Your Project

Go into the project that should receive the CopilotOps assets.

cd C:\SharedProjects\CS_Datafactory_v2

4. Run Dry-Run First

Dry-run shows what would happen without changing files.

npx --yes git+https://github.com/hjahouse/CopilotOps.git#dev install --dry-run

5. Review The Result

Check that only Copilot-specific files are being linked and that .github/workflows is not touched.

If you see missing access, login issues, or unexpected warnings, stop and fix that before applying changes.

6. Apply It

If the dry-run looks safe, run the same command without --dry-run.

npx --yes git+https://github.com/hjahouse/CopilotOps.git#dev install

Common Cases

Repo invite accepted, but command fails Sign in to GitHub in VS Code or Git again. The repo is private, so the machine must authenticate correctly.
You are not inside the project folder Use --target to point the command at the project you want to set up.
You only want to check readiness Run doctor to inspect the framework and target together.
You only want a quick project check Run health to inspect the target project setup.
You need a safe undo Use rollback to restore the backed up Copilot assets.
You want to understand the repo shape Use /sky-map for a simple architecture map.

Commands

Command What It Does When To Use It
install Safely links Copilot-specific assets into the target project. Best one-command setup for invited users.
doctor Checks framework files, version matching, target readiness, Git, and warnings. Use when you want the strongest diagnostic check.
health Checks the current project setup. Quick target check.
validate Checks the CopilotOps framework repo itself. Before sharing or pushing framework changes.
rollback Restores backed up Copilot assets. Use if you need to undo a link or install.

Prompts And Skills

Read-Only Prompts

  • /status-line - fast repo/session status.
  • /sky-health - quick setup check.
  • /sky-doctor - deeper diagnostics.
  • /sky-map - architecture map.
  • /sky-explain - simple explanation.
  • /sky-docs - write docs.

Planning Prompts

  • /sky-fast - small and medium tasks.
  • /sky-task - large or cross-layer work.
  • /sky-debug - bug and root cause work.
Planning prompts stay read-only until the user types APPROVE PLAN.

Safety

What Changes

Only Copilot-specific assets are linked or copied:

  • .github/copilot-instructions.md
  • .github/instructions
  • .github/prompts
  • .github/skills

What It Must Not Touch

  • .github/workflows
  • Any product source files
  • Anything outside the target project you chose

Simple Rule Of Thumb

If you are invited to the private repo, you do not need a separate installer. Open your project, run the dry-run command, and only apply it after the output looks safe.
