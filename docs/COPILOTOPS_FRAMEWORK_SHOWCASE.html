Why This Framework Matters

CopilotOps turns ad hoc AI usage into a repeatable engineering workflow.

Before One big prompt

Every task can become a broad repo scan, repeated context, unclear assumptions, and expensive token usage.

With CopilotOps Focused command

The user chooses a command such as /sky-task, /sky-debug, or /sky-fast.

Result Small specialist lanes

Each lane receives only the task summary, candidate files, and one exact question.

Best Way To Use /sky-task

Give the command a clear backend goal, expected behavior, and any known files or endpoint names. It will inspect only what it needs.

/sky-task
Add validation to the incident summary endpoint.

Expected behavior:
- If CustomerId is missing, return 400.
- Keep existing response shape.
- Follow existing validator patterns.

Known area:
- Incident summary API
- Existing .NET 6 backend patterns

Please produce the plan first. Do not edit until I type APPROVE PLAN.

What happens after this prompt

Classify the task.
Backend validation change, probably API plus service, low to medium risk.

Find candidate files.
Routes, controller, validator, service, DTO, nearby tests or verification paths.

Run lanes in parallel.
API checks contract, Service checks rule placement, Verification defines proof.

Merge one plan.
Files to change, risks, steps, and checks are presented clearly.

Wait for approval.
No code changes happen until the user types APPROVE PLAN.

Backend Workflows

Pick the command based on the shape of the work.

Debug

/sky-debug

Use for exceptions, wrong output, failing checks, null references, mapping bugs, or incorrect status codes.

Output: symptom, root cause, evidence, fix options, side effects, verification.

Feature

/sky-task

Use for endpoint work, service logic, data changes, cross-layer changes, or anything with risk.

Output: full implementation plan, specialist findings, files, risk, acceptance criteria.

Small Change

/sky-fast

Use for compact backend tasks where the change is focused and the risk is low.

Output: short plan, affected files, quick verification, approval gate.

Why Parallel Lanes Save Time And Tokens

The framework does not send the whole repo to every lane. Each lane gets a small mission.

Without lanes

  • One broad prompt asks the assistant to understand everything.
  • The same files and assumptions get reread.
  • Security, data, and performance risks can be mixed together.
  • The final plan can become long and hard to review.

With CopilotOps lanes

  • API lane checks only API impact.
  • Data lane checks only queries, entities, migrations, and SQL risk.
  • Verification lane defines practical proof, including read-only SQL and API checks.
  • The coordinator merges short findings into one plan.

Safe Rollout For The Team

CopilotOps is built to be easy to install, easy to verify, and safe around existing GitHub workflows.

Install safely

Run install --dry-run first. CopilotOps links only Copilot assets and does not touch .github/workflows.

Start simply

Use /status-line, then /sky-health, then choose /sky-fast, /sky-task, or /sky-debug.

Approve intentionally

Planning commands stay read-only until the user types APPROVE PLAN.
